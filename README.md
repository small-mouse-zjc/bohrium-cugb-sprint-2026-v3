# 豆包重做版 v3（2026-11-24）

针对 7 道低于 70 分的题（01 66.33 / 04 62 / 05 64.33 / 07 57 / 08 63.67 / 09 63 / 10 63.67）**换思路重做**。

v2 的做法是"在原包上继续加文件"，被否；v3 的判断是：这 7 题丢分不在"素材不够"，而在**每题只做了一个泛化功能，没有把单点做深，也没有证明它在真实运行中能交出可用成果**。所以每包只留一个单点，围绕它把 40 分实际效果做实，再用可计算指标与缺陷夹具证明机制有效。

## 一、评分结构怎么对应

每题 100 分 = 40 实际效果 + 25 使用增益（质量15/效率5/可验证5）+ 15 创新（新增5/改进5/证据5）+ 10 可靠体验 + 10 生态贡献。v3 每包都按这五块落东西：

| 评分块 | 本包对应的实物 |
|---|---|
| 40 实际效果 | `scripts/` 里 1–3 个可运行脚本 + `examples/expected/` 真实运行产物（不是截图、不是描述） |
| 25 使用增益 | `eval/metrics.py` 可对任意输入重算指标；`eval/protocol.md` 写清同输入对照口径 |
| 15 创新 | `baseline/cases.md` 列出基础 Agent 的典型失败；`examples/selftest.py` 注入这些缺陷，要求检测器**必须命中** |
| 10 可靠体验 | `SKILL.md` 写清触发/不触发、预算降级、五类异常处置；脚本对缺输入显式报错，不静默通过 |
| 10 生态贡献 | `README.md` + `references/method.md` + 输入输出字段表 + `environment/resources.yaml`，下游可直接消费产物 |
